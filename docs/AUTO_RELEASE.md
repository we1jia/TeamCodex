# 自动发布

推送 `main` 后，同一条 `CI & Regression Suite` 流水线依次完成：

1. macOS 回归、安装清单检查与 Windows PowerShell 运行时检查。
2. 选择下一个未使用的版本号，默认按最高正式标签递增 patch；手动提高 `version.json` 的 major/minor 也会保留。
3. 同步 Mac、Windows、插件及后台版本声明，生成中文版本提交，并原子推送 `main` 和新标签。
4. 使用该版本提交的精确 SHA 构建两端安装包；全部成功后发布 GitHub Release 和 SHA256 校验文件。

普通 `codex/**` 分支和 PR 只做检查，不公开发布。快速连续推送时，尚未开始发版的旧提交会跳过，由较新的主分支提交发布。发布中的流水线不会被新推送强行取消。

## 失败与重跑

- 测试失败不会创建版本标签；打包失败不会执行发布任务。
- 已生成标签但打包失败时，在 Actions 中重跑失败任务。完整重跑同一提交也会复用对应的版本提交，不重复递增。
- 并发更新 `main` 时，原子推送会安全拒绝，不强推、不覆盖旧标签。
- 版本提交使用仓库内置 `GITHUB_TOKEN`，不会递归触发新一轮推送流水线。发布由当前 CI 显式调用可复用工作流，不依赖标签推送二次触发。
- 仓库的 Actions 必须允许 `contents: write`。若主分支保护拒绝机器人写入，流水线会明确失败，不绕过保护。
- 自动版本提交会更新远端 `main`。下次本地工作前先 `git pull --ff-only`；不要强推覆盖它。

手动推送 `v*` 标签及手动执行发布工作流仍可用，但标签、源码提交与各处版本号必须一致。当前版本的手写说明取自 `docs/releases/vX.Y.Z.md`；不存在时使用 GitHub 自动生成的更新说明。
