# Team 知识库、素材库与看板

## 已实现的第一版

- 看板：待开始、进行中、等待审核、已完成；状态、成员、工作周历共用任务。
- 任务：主要负责人、协作者、审核人、起止/审核日期、优先级、阻塞原因、验收要求、交付说明、关联资料及操作历史。
- 审核：提交前须指定审核人并填写交付说明；仅指定审核人可通过或退回；退回必须填写原因；审核期间不能替换内容或审核人。
- 工作日历：成员时区、工作日、不可用日期、执行/审核安排、非工作日提示、逾期、未排期列表。不做自动排期和工时推断。
- 知识库：手工文档、文件上传、全文搜索、分类/标签、上传者、私人/项目共享、状态、修订记录。
- 素材库：与知识库共用资料；安全图片预览、原文件下载、当前房间对话附件查阅并整理入库；同内容文件按 SHA-256 复用。
- 对话引用：选择任务或共享资料，预览包含来源 ID、版本、读取时间的上下文，确认后放入 Team 输入框，**不自动发送或执行指令**。
- 原生样式：复用现有主题适配，继承宿主字体/字号，响应浅色/深色及强调色；圆角、边框、间距可在成员设置中配置。
- 更新机制：可见页面每 8 秒读取最新数据；编辑中的表单不被覆盖，保存时校验版本。读取失败后暂停自动同步，显式刷新恢复。

## 身份与权限

房间密钥仅证明可以进入项目，不能证明个人身份。首次启用工作区会创建随机成员 ID 和 256 位成员凭证，服务端仅保存其哈希；凭证存于当前浏览器/客户端本机 localStorage，按 Hub 与房间隔离。显示名和聊天设备 ID 不是凭证，不能用它们冒用私人资料上传者或审核人。

成员需先启用工作区，才能作为任务负责人/审核人选取。原有聊天成员与在线状态不自动变成已认证工作区身份。这是轻量协作身份，不是企业 SSO 或经过管理员核实的实名账户；持有房间密钥的人仍能以任意显示名登记。

私人资料仅上传者可读取，且不进入旧聊天快照、旧 compact 上下文或 SSE 资料广播。共享任务和对话上下文只能关联共享资料。其他成员可上传自己的资料，但不能修订他人的文件。关联了共享任务的资料不能直接改回私人；旧聊天中已经发送的引用不会因后续资料权限变化被撤回。

新文件存放于受鉴权保护的独立 blob 目录，不走原 `/uploads/` 公开路由。**历史聊天图片沿用旧系统的公开上传地址，新模块没有追溯修复旧地址权限**；素材库仅列出当前已鉴权房间明确引用的图片。敏感资料应走新上传流程。

服务端仍是单进程 JSON 存储，仅支持一个 Hub 进程写同一个 DATA_DIR。写入使用临时文件 + 原子 rename，写入失败不提交内存状态。私人权限不防 Hub 系统管理员读取磁盘；不应将有敏感内容的 Hub 无鉴权暴露公网，跨设备连接应使用 HTTPS。

## 数据与资源

```text
DATA_DIR/
  messages.json         # 既有聊天结构保持不变
  workspace.json        # 成员凭证哈希、任务、资料与修订
  workspace-blobs/      # 内容寻址文件，不通过静态目录暴露
```

上传上限 10MB；文本上限 200000 字符。Markdown、TXT、JSON、YAML、TOML、INI 等文本可索引正文；PNG/JPEG/GIF/WebP 通过文件头识别后预览。PDF、Office、音视频等可以保存和下载，尚无文本抽取、转码或 AI 图片识别。SVG/XML 作为纯文本处理，不注入页面执行。密钥检测是启发式辅助，不能替代上传者脱敏。

## API

所有 `/api/workspace/*` 请求均需 `room` 参数和对应房间访问密钥。除登记外，还需 `X-Workspace-Token`。不要把成员凭证写入共享文档或放在 URL。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/workspace/enroll` | `name/kind/presenceId`，返回成员与凭证 |
| GET | `/api/workspace/state?query=关键词` | 权限过滤后的成员、任务、资料摘要和全文匹配 ID |
| PATCH | `/api/workspace/profile` | 自己的名字、时区、工作日、不可用日期 |
| POST | `/api/workspace/tasks` | 创建任务 |
| PATCH | `/api/workspace/tasks/:id` | 修改/审核，必须提供当前 `version` |
| POST | `/api/workspace/resources` | 创建文档或上传 `filename/base64` |
| GET/PATCH | `/api/workspace/resources/:id` | 读取/修订，修改需 `version` |
| GET | `/api/workspace/resources/:id/content` | 鉴权内容与 Data URL（支持原生 RPC） |
| POST | `/api/workspace/attachment` | 用 `messageId/index` 读取当前房间历史图片 |
| POST | `/api/workspace/context` | 用 `taskIds/resourceIds` 构建选定共享上下文 |

UI 仍通过现有 native RPC 访问 API。原生 binding 与轮询兜底共用同一调用 Promise，防止重复执行写操作。服务端返回的工作区数据不会被自动追加到原全局 prompt hook；只有用户显式选择的引用才进入输入框。

## 本地验证与上线边界

```sh
node --test tests/test_workspace.mjs tests/test_workspace_bridge.mjs tests/test_workspace_http.mjs
node tests/workspace_preview.mjs
```

预览脚本只绑定 `127.0.0.1:19931`、创建临时数据目录，不启动或注入真实 Codex。访问 `/workspace` 是独立界面；访问 `/windows/mock-codex-host.html` 可检查同一组件在模拟宿主 Shadow DOM、侧栏、RPC 下的集成。

部署时需要整套更新 `server/`、`inject/`、`ui/`，不能只复制 `sidebar_fullscreen.js`。Windows/macOS ZIP 清单包含工作区、运行时识别和 CDP WebSocket 模块；Docker 既有目录复制会包含新资源。打包应使用干净的 Git 检出，不能把运行中的 `data/`、私人 blob 或本机数据目录指针带入分发包。真实 Codex App 的最终兼容验收应在授权更新后单独完成。

Hub 可直接从工作目录读取静态文件，但已运行的 Node 进程不会自动加载新增后端接口。更新需防止新脚本与旧服务混用。挂载判据同时检查真实 Team 节点；侧栏被宿主重建后恢复入口，不把旧的“已安装”标记当成成功。旧会话没有完整卸载协议时保留页面、草稿和焦点，完整 UI 在下次正常打开客户端时加载。

- 字体按原生菜单控件采样，颜色优先继承 Codex 的语义主题变量；不把 `body` 的正文字号当作按钮字号。
